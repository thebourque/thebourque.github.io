GUMBO — Wave 1: remaining to build, NEPA, BEAD RC, labor $

Wave 1 (Tom/Ben) projects with passings remaining to build > 0. Miles/passings remaining are Contrac-adjusted (core_rules_plan_field_remainder, same method as the Wave/Contrac-remaining page). NEPA overlaps each project's leftover polygon against ESAPTT/NEPARoutes approval lines. BEAD remaining is broken out by give-back Reason Code where a coded point falls inside the leftover polygon. Labor $ / Material $ are the atomic-BOQ mainline remainder (plan qty − field ROQ qty) × plan unit $, split by each Inputs bucket's own labor-vs-material tag; buckets with no tag at that grain (the magic-mile rollup trueup) are shown separately as Unsplit $ rather than guessed into either side — Labor + Material + Unsplit always foots to Mainline $. Pricing resolves via core_rules_atomic_units_authority: this model version's own atomic tables when present, else the Williams-825 authority pin — never a silent $0; every row names which path was used. Two optional checkboxes let you hide exhausted/archived parent rows (no time slot needed) and/or Cohort A/B rows (accounted at lump-sum, not tracked per-project) for a cleaner view of actively schedulable work — both default off, showing every row exactly as before. All filtering and CSV export run locally in your browser — no server, nothing sent anywhere.
